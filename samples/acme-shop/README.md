# Acme Shop sample data

The *Database Internals & Performance* pages run their examples on this dataset: Acme Shop's customers, products, orders, order items and order events, generated by [`seed.sql`](seed.sql) on PostgreSQL 18. The script fixes the random seed, so every run produces the same rows.

| Table | Rows | What it holds |
|---|---:|---|
| `customers` | 100,000 | `id`, unique `email`, `name`, `country` (TH, SG, MY, VN, ID, PH), `created_at` |
| `products` | 10,000 | `id`, unique `sku`, `name`, `category` (12 of them), `price_thb` |
| `orders` | 500,000 | `id`, `customer_id`, `status`, `shipping_country`, `created_at` (2024-12-31 to 2026-10-02, rising with `id`), `total_thb` |
| `order_items` | 1,250,000 | primary key (`order_id`, `line_no`), `product_id`, `qty`, `price_thb` |
| `order_events` | 1,500,000 | `id`, `order_id`, `kind` (placed, paid, shipped), `happened_at`, stored in time order |

Only the primary keys and the unique constraints are indexed; the pages add the indexes they discuss. A few customers order a lot (customer 1 has 2,633 orders), and most orders are delivered (487,245) while about 3,000 are still open. The seed updates `orders` after loading it, so its rows are no longer stored in `id` order on disk; `order_events` is.

## Load it

With Docker and `psql` (any PostgreSQL 18 server works the same way):

```sh
docker run -d --name acme-db -e POSTGRES_PASSWORD=acme -p 127.0.0.1:55432:5432 postgres:18
psql postgresql://postgres:acme@localhost:55432/postgres -c "CREATE DATABASE acme"
psql postgresql://postgres:acme@localhost:55432/acme -f seed.sql      # about a minute; about 310 MB
```

Each page's *Try it* script starts from a fresh copy, so experiments never change the original. To copy quickly, make `acme` a template first:

```sh
psql postgresql://postgres:acme@localhost:55432/postgres \
  -c "ALTER DATABASE acme IS_TEMPLATE true" -c "ALTER DATABASE acme ALLOW_CONNECTIONS false"
psql postgresql://postgres:acme@localhost:55432/postgres \
  -c "CREATE DATABASE try_it TEMPLATE acme STRATEGY FILE_COPY"
```

Plans and row counts should match the pages. Timings, and buffer counts that depend on what is already cached, will differ on your machine; statistics gathered by your own `ANALYZE` can differ slightly too, because `ANALYZE` reads a random sample.
